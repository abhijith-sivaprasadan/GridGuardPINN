# GridGuardPINN v1.0 — Independent-style internal QA audit

**Audit date:** 2026-10-09. **Scope:** repository structure, basic code paths, current CI, routing safety claims, checkpoint loading, numerical evidence, scientific reporting and release readiness. **Reviewer:** automated code review, not independent power-system certification.

**Verdict: CONDITIONAL / NOT YET FORMALLY RELEASED.** The core model, reference adapter, benchmark scripts and research findings are substantial. Passing CI and prior ANDES workflows demonstrates reproducible behavior on frozen scenarios; it does not establish adversarial input correctness, operational safety, or publication-level independent verification.

## Confirmed and fixed during this audit

**QA-001 (P1, corrected):** `andes_router.route_andes_case` checked `math.isfinite(float(value))` but later compared the **unconverted original** values to floats. Numeric-looking strings and boolean values could pass validation and produce TypeError or implicit integer semantics, violating the advertised fail-closed behavior. The router now accepts only exact built-in int/float numeric types and rejects invalid values before comparisons. Regression tests cover numeric strings, bool, and None. This is a **runtime-validation fix**, not a scientific model or threshold change. Status: code and tests committed; see CI for verification.

## Scientific claim audit

1. **Physics informed vs data-only:** 11.9–19.8% fresh-ID mean error improvement across exactly three seeds is supported by frozen ablation; claims of universally superior OOD calibration are **not** supported.
2. **Topology descriptor:** ~29.5% reduction in across-seed median unseen-location composite error is an aggregate with improvement in 2/3 seeds; it does **not** justify unseen-bus surrogate acceptance. Residual-only false accepts (3–4 per seed) remain a prominent negative finding.
3. **New-duration accuracy:** 76/84 accepted seed-case evaluations with zero *observed* inaccurate acceptances on same-network scenarios is supported, but should not be called cross-network generalization or safety proof.
4. **Performance:** three paired randomized rounds reported 1.568–1.954× mixed-workload speedup, with bus-cluster bootstrap intervals 1.241–2.022×, 1.430–2.084×, and 1.867–2.035×. These are valid **descriptions of this runner/workload**; intervals only resample seven buses and cannot establish industrial throughput.
5. **Release status:** package version 1.0.0 and a release-candidate branch are not evidence of a published release; no published GitHub Release has been observed.

## Recommended release decision

Keep the existing physics results and benchmarks frozen. Do **not** retrain or alter thresholds to fix engineering QA. Resolve QA-002 to QA-006 and add adversarial regression tests before presenting the project as fully QA-cleared. It can already be presented as an **evidence-backed research demonstrator** with honest restrictions.

## Follow-up remediation (9 October 2026)

- **QA-004 substantially resolved:** CLI no longer accepts caller-provided inertia, damping or frequency. It obtains these from the canonical installed IEEE-14 ANDES system, verifies ANDES 2.0.0, SHA-256 `2c6c792c29f0e8a13301b1b029f2289f940b0fd5a765c934c25d1ce83948bd7b`, and ordered GENROU buses `(1,2,3,6,8)`. The CLI writes this provenance into `routing.json`. The original historic training checkpoint itself does not embed this SHA, so the inference-side pin does not retroactively prove its training provenance.
- **QA-005 resolved for default CI coverage:** standard `.github/workflows/ci.yml` now includes a mandatory `integration` job installing PyTorch and ANDES 2.0.0, executing the full test suite and real-ANDES checkpoint-roundtrip smoke. New checkpoint-digest, explicit-encoding and wrong-protocol rejection tests were added. This does not itself configure GitHub branch-protection required status checks.
- **QA-007 corrected:** the ANDES extra no longer silently omits its dependency on Python 3.10; unsupported environment resolution will fail instead of falsely appearing complete.
- **QA-008 partially resolved:** routed grid must span the full 0–2-second interval; arbitrary nonstandard intermediate sample counts remain available to research callers and should not be used for fixed-protocol quality comparisons.
- **QA-006 remains open:** no immutable published GitHub release with preserved artifacts has been verified.
- **QA-009/010:** scientific and academic-scope limitations are not runtime bugs and remain explicitly disclosed rather than declared repaired.
- **QA-011/012:** richer per-decision residual metadata and a reproducible fully locked dependency environment remain desirable. They should not be mislabeled closed by green CI.

This addendum supersedes older open-status labels in the initial table where contradictory. The latest CI outcome must be checked against the remediation commit, not an older successful run.

## Publication-stage remediation

- QA-010: The paper now links verified external scholarly background and two source-grounded publication vector figures. This is not a comprehensive literature review or peer review.
- QA-011: Runtime results and the CLI now report physics residual scores, thresholds and observed reference-solve elapsed times, plus canonical IEEE-14 case SHA-256 and generator ordering in the CLI.
- QA-012: Publication automation records an exact resolved Python environment, selected source commit and SHA-256 checksums alongside the original evidence archives. This is a reproducible environment snapshot, not a cross-platform frozen lockfile.
- The original model-training checkpoints do not contain a contemporaneous case-file fingerprint; inference-time case verification cannot repair that historical absence.
- Publication remains incomplete until GitHub confirms the v1.0.0 tag and all durable evidence assets. No scientific thresholds, trained weights or experimental results were retuned.

External-grid evaluation, scientific peer review and production safety remain outside the v1.0 research demonstrator.
